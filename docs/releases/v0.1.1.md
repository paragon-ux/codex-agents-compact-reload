# v0.1.1 - Lifecycle, handled

The hook now behaves like a good guest: stale neighbors cannot interrupt the current project, installation has a companion setup workflow, and cleanup has a scoped exit instead of an improvised deletion command.

## Highlights

- Fixed stale-registration isolation so a deleted unrelated project cannot stop compaction in a valid or unregistered project.
- Preserved fail-closed behavior when the current matching registration is invalid.
- Added `$codex-compact-reload-setup` for verified, dry-run-first setup.
- Added `$codex-compact-reload-cleanup` and `scripts/uninstall.mjs` for named deregistration or complete removal.
- Preserved unrelated hooks and added a recoverable `hooks.json` backup before complete uninstall.
- Added a frozen manual/automatic Codex host-acceptance protocol.
- Clarified that Codex hook trust does not independently attest the installed script bytes.
- Licensed the project under the MIT License.

## Compatibility snapshot

This release was developed and locally verified with:

- Node.js 22; and
- Git for Windows.

CI verifies the package on Windows and Linux with Node.js 20, 22, and 24. The Codex version is an evidence-bound compatibility snapshot, not a declared minimum.

## Remaining acceptance boundary

Before making the hook a hard dependency of a high-assurance workflow, run `docs/HOST-ACCEPTANCE.md` on the exact installed release. That campaign must demonstrate fresh marker/hash injection after manual and automatic compaction, including every deployment mode being claimed.

An incomplete host campaign does not make this public utility release invalid; it limits the stronger operational claim.
